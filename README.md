## Задание 3
Очередь вместо прямой правки баланса: продюсеры пишут событие, воркер применяет.
- Воркер лочит баланс абонента через `FOR UPDATE SKIP LOCKED`: порядок операций цел, параллельные воркеры не мешают друг другу.
- На пачку событий один `UPDATE` баланса; история хранит остаток после каждой операции.
- Овердрафт: `REJECTED` с причиной, плюс `CHECK (balance >= 0)` как страховка.
- `UNIQUE (op_type, src_id)` защищает от двойных начислений.
- Сбой одного абонента не валит остальных (коммит по абоненту).

Что улучшил бы: архивация/партиционирование очереди, лог-таблица ошибок, ретраи, при серьёзной нагрузке - Oracle AQ.
